---
title: Sync to the platform
description: Push each app's configuration into the environment its processes read, so apps boot on the last values even when the config server is down.
---

The control plane can push an app's configuration to wherever its processes read their environment:
a PaaS's variables, a Kubernetes Secret, a `.env` on a host. The control plane stays the source of
truth, with the console, versions and audit. The app keeps reading plain env variables. If the
control plane is down, the app still boots on the last values the platform holds.

This is the pattern of External Secrets or Doppler: the platform delivers the values, and the app
never calls the config server at boot.

## A target

A target knows the platform. It receives what changed and applies it:

```ts
import type { ConfigSyncTarget } from '@adonis-agora/config'

const myPaas: ConfigSyncTarget = {
  name: 'paas:shop',
  async apply(change) {
    // change.set:    { RESEND_API_KEY: { value, secret: true }, MAIL_FROM: { value, secret: false } }
    // change.remove: ['OLD_FLAG']  (keys removed from the config since the last push)
    // change.mode:   'delta' on a new version, 'full' from `config:sync`
  },
}
```

Keys become env names the same way as everywhere else in the lib: `resend.api.key` becomes
`RESEND_API_KEY`. Secret values arrive decrypted, flagged `secret: true`, so the target can store
them as secrets. Every push reveals them under the actor `config:sync:<target name>` in the audit.

## Rules

```ts title="config/config.ts"
export default defineConfig({
  topology: 'control-plane',
  // …
  sync: {
    rules: [
      {
        app: 'shop',
        target: myPaas,
        // never pushed nor deleted: what the app needs to reach the control plane
        keep: ['CONFIG_URL', 'SERVICE_CLIENT_ID', 'SERVICE_CLIENT_SECRET'],
      },
    ],
  },
})
```

- **On every new version** (console, command, MCP, rollback), the change is pushed as a delta: what
  is set, plus the keys removed since the last push. Writes made within `debounceMs` (default
  2 s) go out as one push.
- **`node ace config:sync`** pushes every variable of each app (`--app=shop` for one). Run it after
  adding a rule, or when the platform drifted. It prints names and counts, never a value.
- **A failing target** is logged and does not fail the write. The next version, or
  `config:sync`, pushes again.

When the platform applies variables only on a deploy or a restart, a change reaches the processes
then. For values that must change without a restart, read them with `config.get()` from a tenant.
