title: MCP tools

With `@adonis-agora/agent/mcp_provider` registered, the control plane adds its tools to the app's
developer MCP endpoint (`/mcp/agora`). No app config: the provider registers them at boot, and each
call is authorized by the console's `authorize`.

## Reads (always listed)

| Tool | |
| --- | --- |
| `config_list_scopes` | apps, environments and labels that hold something |
| `config_list_entries` | entries of a scope, with `search`, `secret`, `reloadable`; `{ items, next }` |
| `config_get_entry` | one entry; a secret is masked unless the console may reveal it, and the reveal is audited |
| `config_list_versions` | immutable versions, newest first; `{ items, next }` |
| `config_get_version` | one version exactly as it was |
| `config_diff_versions` | added/removed/changed keys between two versions |
| `config_list_audit` | who changed what and why, filtered by `key` / `action` |

## Actions (opt-in)

These are hidden and uncallable unless the app opts in on the dev endpoint:

| Tool | |
| --- | --- |
| `config_set_entry` | value or vault reference, secret/reloadable flags, reason |
| `config_unset_entry` | remove an entry (destructive) |
| `config_rollback` | copy a past version into a new one (destructive) |

```ts title="config/mcp.ts (the control plane)"
devTools: {
  // Only these tools may run as actions; the rest of the endpoint stays read-only.
  actions: { config_set_entry: authorizeByToken({ token: env.get('MCP_TOKEN') }) },
}
```

The action vocabulary is the agent's: `'refuse'` (default), `'execute'`, a list of lib ids or tool
names, a map of authorizers, or a function. See the agent's docs for the full shape.

## Audit and secrets

Every write records `mcp:<caller id>` as the actor, exactly like the console records its viewer and
the CLI records `cli:<os user>`. A secret is returned only when the console's `revealSecrets` is on,
and the read is written to the audit trail as a `reveal`.

The tools use the same `ConfigAdmin` service as the console and the commands: same validation, same
versioning, same masking — a tool can never do more than the console it belongs to.
