---
title: Secrets
description: Never stored in plain text — encrypted at rest with the app key, or resolved from a vault.
icon: Lock
---

An entry is a secret when it was written as one (`secret: true`), or when its value is a `vault://`
reference. Secret values are **never stored in plain text**.

## Encrypted at rest

No configuration: a secret is encrypted with the **app's AdonisJS encryption service**, the same one
`config/encryption.ts` configures (`APP_KEY`, the key list, the driver). This package never keeps a
key of its own.

```ts title="config/encryption.ts (already in an AdonisJS app)"
import { defineConfig, drivers } from '@adonisjs/core/encryption'

export default defineConfig({
  default: 'app',
  list: { app: drivers.aes256gcm({ id: 'app', keys: [env.get('APP_KEY')] }) },
})
```

- The ciphertext is the service's (`<id>.<v1:ciphertext>.<iv>.<tag>`), bound to the purpose
  `agora-config`: another feature of the app cannot decrypt a config secret by accident.
- Key rotation is the service's: encryption uses the first key, decryption tries every key. Add the
  new key first, let old values be read, then re-save them.
- A dump of the table, the memory store, the audit trail or a backup holds ciphertext only; a value
  that cannot be decrypted (wrong key, another codec) fails loudly, never as plaintext.
- For a KMS-backed store, `secrets: { codec }` replaces the service with your `SecretCodec`:

```ts
defineConfig({ topology: 'control-plane', verifyTenant, secrets: { codec: myKmsCodec } })
```

- Writing a secret with no encryption service available is an **error**, not a silent plaintext
  write. `node ace agora:doctor` reports it as `config.secrets-key`.

The tenant's snapshot is a copy of what its token may read, written on the app host (`0600`). Give a
tenant `config:secrets:read` only when it truly needs secret values at boot; otherwise the snapshot
never holds them.

## Vault references

A value can be a reference resolved when it is read:

```ts
{ key: 'stripe.secret', value: 'vault://aws/prod/streaming#stripe_key', secret: true }
```

```ts title="config/config.ts (the server)"
defineConfig({
  topology: 'control-plane',
  verifyTenant,
  vault: {
    async resolve({ provider, path, field }) {
      // authkit's vault packages, AWS Secrets Manager, HashiCorp Vault, …
      return mySecretManager.read(`${provider}:${path}`, field)
    },
  },
})
```

The reference is stored; the resolved value is not. A reference that cannot be resolved is served
`masked: true` and logged — never as a wrong or empty value.

## Who may read a secret

| Caller | Needs | Gets |
| --- | --- | --- |
| a tenant with `config:read` | — | `masked: true`, no `value`, the `vault` reference still visible |
| a tenant with `config:secrets:read` | `config:read` too | the decrypted value, or the vault-resolved value |
| the console | its `authorize` gate; an explicit reveal, audited | the value |
| the CLI / an MCP read | `--secrets` on `get`/`env`/`pull`, or `revealSecrets` for MCP; audited per key | the value |

The masked entry carries no `value` key at all, so a client cannot confuse "you may not read this"
with "this is empty".

## The audit trail

```json
{
  "actor": "ann@example.com",
  "action": "reveal",
  "key": "stripe.secret",
  "version": 7,
  "at": "2026-11-14T18:00:00.000Z"
}
```

`set` and `unset` rows keep before/after entries, themselves sealed. A reveal row records who read
which secret at which version.
